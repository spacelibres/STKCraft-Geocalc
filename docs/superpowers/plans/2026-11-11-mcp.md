# MCP Server Implementation Plan

**Goal:** Expose the existing geometry and GF command paths through a local stdio MCP server without duplicating numerical algorithms.

**Architecture:** `src/mcp/mod.rs` owns JSON-RPC lifecycle, discovery and resources. `catalog.rs` defines typed input schemas and CLI-field mappings for the 24 geometry/GF families. `backend.rs` validates kernel context, invokes fixed sibling executables without a shell, and preserves raw and structured outputs. `src/bin/mcp_server.rs` is the stdio entry point.

- [x] Add protocol and real subprocess tests; observe missing-server failure.
- [x] Implement legacy initialization and modern request metadata, tool/resource discovery, protocol errors and notification silence.
- [x] Implement allowlisted typed family mappings and complete CSV adapter; preserve exact backend doubles and stdout isolation.
- [x] Verify real Moon state and native GF distance windows against direct backend output; test invalid arguments, missing kernels, unknown tools and non-finite fields.
- [x] Document build/install/client configuration, every tool schema and CSV contract in English; provide the actual schemas to the Agent Skills author.
- [x] Run feature-enabled and feature-disabled checks and report the verified checkpoint to the root agent.

The parent task explicitly authorizes this design and coordinates Cargo metadata, library registration, package version and publication. No numerical source modules or existing CLI dispatchers will be edited for the MCP adapter.

Final publication acceptance is recorded separately by the complete strict gate and GitHub release workflow.
